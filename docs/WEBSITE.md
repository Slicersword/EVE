# GitHub-hosted website and offline copy

The build guide is hosted at **https://slicersword.github.io/EVE/** directly from
[Slicersword/EVE](https://github.com/Slicersword/EVE). GitHub stores the source,
builds the pages and serves the website. The website does not use ChatGPT hosting,
ChatGPT login, an OpenAI API key or a paid AI service. Your ChatGPT subscription
is separate from this website.

## How publication works

The repository already has GitHub Pages enabled for **main / root**. GitHub's
built-in Jekyll build renders the Markdown under docs using the manual layout,
local styles and JavaScript. Each push to main triggers **Verify EVE**, which checks
the code and rendered pages, then runs **Publish GitHub Pages** with the validated
artifact. GitHub's built-in **pages build and deployment** may also render the
same branch source; both use the same Jekyll documents and layout.

The guide, search index, navigation and code snippets come from the same commit.
The footer shows the GitHub source revision. No separate copy needs to be uploaded
to ChatGPT, and no custom domain is required.

The repository must remain public and GitHub Pages must remain enabled for the
intended GitHub Free setup. GitHub's service terms and usage limits still apply.

## Update the website from Git

1. Edit the root README or a Markdown document under docs.
2. If changing the generated software guide, update its recipes and regenerate it
   with the commands below.
3. Commit and push to main through GitHub or a local Git checkout.
4. Wait for **Verify EVE → Publish GitHub Pages** to succeed. Open its deployment
   URL and refresh the page. The footer identifies the published revision.

```bash
python3 tools/stage.py guide > docs/SETUP_GUIDE.md
python3 tools/check_repo.py
```

These commands belong on a development checkout; they do not run motors or
commission hardware. Keep config/local.json, data, tokens and downloaded models
out of commits.

## Hosting configuration

| Setting | Value |
|---|---|
| Provider | GitHub Pages |
| Repository | Slicersword/EVE, public |
| Publishing source | Main/root Jekyll source; validated Actions artifact deployment |
| Branch / folder | main / root |
| Website configuration | _config.yml |
| Shared page layout | _layouts/manual.html |
| Live search data | search-data.js, generated by Jekyll from the documents |
| Assets | site/assets, stored in Git |
| ChatGPT subscription or API key | Not used by the website |

If configuring a fork, enable Pages in Settings → Pages, select its main branch
and root folder, and adjust url/baseurl/repository in _config.yml. Do not enable
a competing Pages workflow that overwrites the branch-published output.

## Keep an offline website copy

The Node builder remains available as a separate, self-contained offline export
with complete source listings and raw-file downloads. Install Node 22 (CI target)
and Python 3.11+, then run from the repository root:

```bash
node tools/build_docs.mjs
python3 tools/check_site.py
```

Open dist/index.html and keep all of dist together. It has no backend, trackers,
external fonts or CDN. Search works from file://; if your browser restricts the
clipboard there, select and copy the code manually.

You can also download **eve-documentation-offline** from a successful Verify EVE
Actions run, extract it, and open index.html. GitHub artifacts have a retention
period, so download a copy if you want to keep that exact version permanently.

For a local development preview:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Open http://127.0.0.1:8000 and stop with Ctrl+C. This documentation server is
separate from the robot's token-protected control API.

## Validation

Verify EVE checks the offline build and also runs the same Jekyll builder used by
GitHub Pages. The rendered site is checked for missing files, broken navigation,
anchors, search entries and unexpected external assets. The hosted Pages build
must also finish successfully before a new version is considered published.
